### The defect this turned up

**Fridge Clearer stage 1 leaks allergens into the offered ideas.** The same
adversarial profile got three ideas back, two of which contained its allergens:

```
"Spinach Potato Bake"    — clean
"Cheesy Potato Skillet"  — CHEESE (Lactose/Dairy)
"Spinach Walnut Salad"   — WALNUTS (Tree Nuts)
```

Stage 2 then produced a clean recipe, so nothing unsafe is cooked — but the
ideas screen is user-facing generation output, and offering a dairy-allergic
user a "Cheesy Potato Skillet" is the surface working against the profile they
filled in.

Detection is built (`allergensInIdeaText`). **The action is not**, and is
Harris's ruling, because the obvious fix has a real failure mode: filtering
ideas can leave fewer than three, and dropping to zero would break the screen.
Regenerating costs a second stage-1 call. Annotating ("contains dairy") is the
cheapest and least destructive. Not decided here.

## A2 — the deterministic allergen check

Built: `lib/services/allergen_guard.dart` over
`lib/data/allergen_synonyms.dart`.

It inspects generated **ingredient names**, whole-word, case-insensitive, with
optional plural. Two deliberate limits:

- **Step prose is not scanned.** A step saying "unlike a classic carbonara,
  there is no egg here" is *correct*, and a rule that fires on recipes doing
  the right thing is a rule people learn to ignore.
- **Whole-word matching is load-bearing, not stylistic.** Real output used
  **nutritional yeast** as the vegan substitute for parmesan — for exactly the
  dairy-avoiding profile. A substring matcher would have flagged the substitute
  as the allergen it replaces. `nutmeg` and `eggplant` are the same class.

Ordering: **third and last**, after compatibility and safety, so it has the
final say on what is served and a correction it wins cannot be re-broken by a
later timing retry. Correction retry ×2, then fail-open with a loud log, and
two new cost surfaces (`*_allergen_retry`) so its rate is readable on its own.

### Fail-open or fail-closed — argued, not decided (PENDING HARRIS)

- **For fail-closed:** every other fail-open in this app costs a worse dinner.
  This one costs an allergic reaction. A user who selected "Tree Nuts" made a
  medical statement, and serving them walnuts after two failed corrections is
  worse than serving nothing.
- **For fail-open:** the guard is a *synonym list*, not a lab test. A false
  positive blocks a good recipe, and the user sees nothing either way — there
  is no error surface to fail *into*. Failing closed into a blank screen reads
  as "the app is broken".
- **My view: fail closed, but only once a real user-facing state exists** —
  "we could not build this safely, here is why". Failing closed today trades
  one bad outcome for a different one. Until that surface exists,
  fail-open-with-a-loud-log is the honest interim, and the log is the part that
  must never be dropped.

## HALF B — the redesign, by class

| Change | Class |
|---|---|
| Screen rebuilt to the §2 composition | `_ProfileScreenState.build` |
| **Language card deleted** | `_languageOptions` removed |
| Every explainer paragraph deleted | all `subtitle:` args gone with `ProfileSectionCard` |
| Radio circles + mixed styles → one champagne fill | **new** `SelectionChip`; `DietOptionTile` and `ConfidenceOptionRow` **deleted** |
| Card chrome without a headline | **new** `_ProfileCard`, `_CardLabel`, `_QuietRow`; `ProfileSectionCard` **deleted** |
| Guidance rows, single-select, no radio | **new** `GuidanceRow` |
| Comfortable Techniques, read-only | **new** `_ComfortableTechniques`; `_unmarkComfortable` **deleted** |
| Dev section, dashed ghost | **new** `_DevSection`, `_DashedBorderPainter` |
| Dark-forest CTA → terracotta | `_AnonymousAccountPromptCard` |
| Save button → autosave | `_scheduleAutoSave`, `_save({silent})` |

**The Save Profile button is gone**, and that is what makes the one-CTA rule
achievable: with a save button on screen the terracotta CTA would have been
"save", not "Secure my account". Selections now persist as they are made
(600 ms debounce), and the old behaviour of popping the route on save — which
made Profile feel like a form you submit — went with it.

**`SelectionChip` and `GuidanceRow` are public**, deliberately: `ProfileScreen`
reads `Supabase.instance.client` in `build`, so the whole screen cannot be
pumped without a live client, and public widgets are what let the kit rules be
asserted at all.

## Spec lines not satisfied

1. **§2.6 "two-line data-on-device note"** — the existing account card's
   wording was kept as-is rather than rewritten to two lines. It is
   persona-batch content and rewriting it would have been authoring copy.
2. **§6 device checks** are Pixel checks and need Harris.
3. **A4's "must NEVER rescale an open recipe" test** is asserted structurally
   (the Profile stepper writes only `householdServings`; the overview owns the
   live scale, and its own test file covers rescaling) rather than by a
   cross-screen integration test. The two surfaces share no state to leak
   through.

## Ambiguities

- **"Guidance level LIVE"** is a payload verdict with weak output evidence. One
  beginner-profile sample cannot prove verbosity adapts between levels. Called
  LIVE because it reaches the model as an explicit hard constraint; a real
  A/B across the three levels is a separate measurement and is not claimed here.
- **Display name** can have no recipe-surface output evidence at all — the JSON
  schema has nowhere to address the user. Called LIVE on payload evidence, with
  the limit stated.
- **The 14 allergen keys** were treated as already-signed (they are the shipped
  chips); only the synonym lists are offered for signature.

## Scope flags

**Grew:** the allergen guard is new work that Half A's verdict did not strictly
require — the prompt was already live. Built anyway because A2 says the
deterministic check is added "if absent" regardless, and it is the only
guarantee. Two new cost surfaces came with it. `_save` gained a `silent` mode
and the empty-name snackbar became a focus request, both consequences of
autosave.

**Held:** no migration (the `language` field stays). Auth untouched — only the
button restyled. Nothing from the custom-creator card was started. The stage-1
allergen leak was detected and reported, **not** fixed, because every available
fix has a failure mode that needs a ruling.
